# Applied Changes Feedback and Follow-up Workflow

## Why

When reviewing applied changes in OpenSpec, users often identify additional work, improvements, or related features they'd like to explore. Currently, there's no clear guidance on what the most natural next steps should be in the OpenSpec workflow. This creates uncertainty about whether to:

1. Regenerate the design and tasks for the existing change and run them again
2. Open a completely new change for the follow-up work
3. Some other approach depending on the context

Without clear patterns for post-implementation feedback and follow-up work, teams may handle similar situations inconsistently, leading to fragmented knowledge and unclear change histories. The OpenSpec workflow should provide natural, intuitive guidance for what happens after a change is applied and new insights emerge.

## What Changes

### Post-Implementation Feedback Flow

- Define clear decision patterns for different types of follow-up work discovered during applied change review
- Add UI affordances to applied changes that guide users toward the appropriate next steps
- Establish workflow conventions for when to iterate on existing changes vs. create new ones
- Create clear connections between original changes and their follow-up work for knowledge continuity

### Success Metrics

- Users can quickly identify the right workflow action when reviewing applied changes
- Follow-up work maintains clear relationships to original changes
- Teams develop consistent patterns for handling post-implementation insights
