Chatbot Workshop: TDD for AI

The Specification IS the Test.

Build a working, tested chatbot in under 4 hours using Test-Driven Development principles. This workshop brings Product, Engineering, and Design together to collaboratively define, build, and refine AI-powered conversations.

The Core Discipline​

Traditional software testing verifies that code behaves correctly. AI testing verifies that conversations behave correctly.

In this workshop, you'll learn the TDD cycle for AI development:

  1. Specify (RED) — Write test cases that define expected behavior. Run them. Watch them fail.
  2. Implement (GREEN) — Write the system prompt. Run tests. Iterate until they pass.
  3. Refine (REFACTOR) — Add edge cases from user testing. Confirm no regressions.

The tool we use: promptfoo — a CLI that runs your tests and shows pass/fail results everyone can see.

Getting Started​

Prerequisites​

  • Python 3.8+
  • A free Groq API key (no credit card required)
  • 5 minutes for setup

Quick Setup​

# Clone the starter repo
git clone https://github.com/your-org/chatbot-workshop-starter
cd chatbot-workshop-starter

# Create virtual environment
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Configure API key
cp .env.example .env
# Edit .env and add your GROQ_API_KEY

# Run your first test (should fail!)
promptfoo eval

Writing Test Cases​

All assertions use llm-rubric — describe expected behavior in plain English.

Anatomy of a Test​

tests:
  - description: "Human-readable test name"
    vars:
      query: "What the user says"
    assert:
      - type: llm-rubric
        value: "What good behavior looks like"

Test Categories​

CategoryPurposeExample
Happy PathCore functionality"Offers to help with the return process"
GuardrailsWhat NOT to do"Does not discuss competitor products"
TonePersonality/voice"Acknowledges frustration with empathy"
Edge CasesUnusual inputs"Handles gibberish input gracefully"

Common Assertion Types​

# Behavioral expectation (recommended default)
- type: llm-rubric
  value: "Response is helpful and on-topic"

# Must contain specific text
- type: contains
  value: "return policy"

# Must NOT contain text
- type: not-contains
  value: "Amazon"

# Combine multiple assertions
assert:
  - type: llm-rubric
    value: "Response is empathetic"
  - type: not-contains
    value: "I don't know"

Common Commands​

# Run all tests
promptfoo eval

# Open web UI for detailed results
promptfoo eval --view

# Run without cache (force re-evaluation)
promptfoo eval --no-cache

# Filter tests by description
promptfoo eval --filter-pattern "empathy"

Troubleshooting​

IssueSolution
GROQ_API_KEY not setCopy .env.example to .env and add your key
Tests always passMake your llm-rubric more specific
Tests always failCheck system-prompt.txt isn't empty or all comments
Rate limit errorsWait 1 minute, or switch to OpenRouter backup
YAML parse errorCheck indentation (2 spaces, no tabs)
