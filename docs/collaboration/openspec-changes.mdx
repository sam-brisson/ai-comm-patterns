## How It Works

Changes flow through four stages, each triggered by a slash command:

**1. Exploring** (`/opsx:explore`)

Start by exploring an idea. Run `/opsx:explore` with a conversation transcript to analyze the discussion, identify key themes, and document insights. This creates the initial change folder with exploration notes.

**2. Proposed** (`/opsx:propose`)

When ready to formalize, run `/opsx:propose` to generate the full artifact set: proposal.md (the why and what), design.md (the how), and tasks.md (the implementation breakdown). A PR is created for review.

**3. Applied** (`/opsx:apply`)

With artifacts approved, run `/opsx:apply` to implement the change. The system executes the tasks, builds the feature, and captures any deviations from the plan. Another PR documents what was actually built.

**4. Archived** (`/opsx:archive`)

Once complete, run `/opsx:archive` to move the change to the archive. This captures final learnings, documents what shipped vs. planned, and makes the knowledge searchable.
